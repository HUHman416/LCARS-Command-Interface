# Version 31.5.10 Development — TOS Resin Keys and Bridge Ambiance

The operator requests the clear, glossy cast-resin appearance of the supplied original-console button photographs. Physical keys use curved highlights, refracted edge light, internal reflected light, and inset optical shadows inside their existing black mounting sockets. The finish covers header, sidebar, Tasks/Tray/Power, selector, command-deck, footer, compact, import, and horizontal rocker controls. Key geometry, bank spacing, readable legends, handlers, focus, disabled states, rocker tilt, and ON/OFF text remain. Reflections are static; the housing and information glass remain matte.

A TOS-only AMBIANCE key sits directly below Computer Operator in the header. It is off by default and persists locally. The operator confirmed use of the full original `tos_bridge_1_activate.mp3` (257.688 seconds), bundled as `tos-bridge-ambiance.mp3`. Manual activation begins at 0:04, fades in over 1.8 seconds, and repeats from 0:04 whenever the recording ends. Turning it off fades out over 650 milliseconds. It follows the existing Interface Sound volume and sound toggle, with an explicit MUTED indication.

When ambiance is already enabled at startup, the full recording plays from 0:00 without the old excerpt’s fade-out, then repeats from 0:04. If startup audio is disabled, ambiance begins directly at 0:04 with its fade-in. With ambiance off, TOS retains the previously approved ten-second startup excerpt and its second-seven-to-ten fade; other families retain their original startup cue. One shared runtime owns audio for both Electron bootstrap and renderer so they cannot double-play. Detached views, remote terminals, safe mode, and renderer recovery suppress background ambiance. Theme changes suspend the bridge bed. Browser autoplay restrictions expose a PLAY key to resume it.

The runtime validates audio responses, cancels superseded loads, cleans up blob URLs, and handles failed playback. Deterministic tests cover looping, fades, startup handoff, concurrent startup callers, rapid toggles, pending-load cancellation, theme changes, mute/volume, blocked playback, media errors, secondary windows, and unload cleanup. Both renderer builds and the JavaScript/Python regression suites pass. TypeScript retains the seven pre-existing diagnostics; this change adds none. Visual checks include desktop, portrait, and short landscape. Actual Windows/Android audio-device playback is not locally verified.

The 31.5.9 all-section information displays and Computer wording, fonts, key/updater/error sounds, other console families, Version 30 Stable, and reserved 31.6 milestone remain. The updater compares numeric version components, so 31.5.10 sorts after 31.5.9.
